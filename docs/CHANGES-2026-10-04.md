# JobScore fixes — 4 October 2026

All application edits were applied to this existing project folder. Changes were described in chat before editing. Existing local changes were retained; no checkout, clone, database reset or credential replacement was performed.

## Backend and processing

- New jobs created in practice mode are authored jobs, so they appear in the default job list. Startup repairs the old example flag on authored jobs while preserving the three seeded examples.
- Matching requests reuse an active run only if its tasks cover every requested eligible profile version. A single-candidate or applicant-only run cannot swallow a full-pool search.
- Requirements can be confirmed while uploads or another job are processing. Explicit matching and reassessment requests wait in the persisted queue; the worker retains its one-task AI / two-task practice concurrency limit.
- Other-role requests can wait behind other work. A duplicate active exploration for the same profile version is still rejected.
- Deleting profiles recalculates affected run totals and closes empty runs. Retry immediately restores active progress, clears the previous error, and resets the queued stage and lease.
- Correcting failed resume evidence makes the new version ready for assessment. Correction versions include their document hash for cache ownership and cleanup.
- Every upload file has its own database savepoint. A failure removes that file's incomplete records and raw upload, while allowing valid files in the batch to continue.
- CSV manifests reject missing identities, filenames, dates, permissions, extra columns in a row, invalid encoding and invalid application status. Blank matching permission cannot silently become consent.
- Resume replacement retains the rejection date alongside the existing lifecycle and interview metadata.
- Blank job titles are rejected after whitespace trimming; criterion identifiers have a bounded nonempty length.
- Monthly monitoring averages are withheld by the API for fewer than five assessments, consistent with the screen.

## Recruiter screens

- Requirement drafts track their saved revision after both saving and the save step of confirmation. A failed approval no longer leaves the screen using the previous revision.
- Background job refreshes preserve unsaved requirement edits.
- Overlap acknowledgement reflects the current edited criteria and resets when the overlapping pairs change. Confirmation requires acknowledgement when overlaps exist.
- Removing the final criterion is disabled; disabled criteria show zero score weight.
- Comparison selection removes assessment IDs that are no longer in the current match results. Comparison errors stop the loading indicator.
- Candidate dialogs reset previous review mutation state and simulator targets between candidates.
- New-job dialogs reset fields/errors on reopening. Talent management resets the previous reason; upload source changes clear the previous manifest; other-role mutation state resets between profiles.
- Uploading/extracting candidates keep match polling fast even before an assessment run exists. Monitoring refreshes automatically.

## Using the update

Stop the existing launcher with Ctrl+C. In this folder, run:

```powershell
.\.venv\Scripts\python.exe run.py
```

Then refresh the browser. Startup also repairs previously hidden authored jobs. No database reset is needed.

These checks establish the tested behavior. They cannot guarantee future provider uptime/quota, arbitrary model output quality, or that untested inputs contain no defects.
